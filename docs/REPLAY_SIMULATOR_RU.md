# Симулятор по списку постановок

Python 3.11+ и Git. Этот путь использует закреплённый cr-bot и не требует Rust,
maturin, CV-моделей или GPU. Расширенный набор правил содержит 109 обычных карт
уровня 11. Исполняемость не равна подтверждённому совпадению с реальной игрой.

## Запуск на Windows, Linux и macOS

```shell
python setup_simulator.py
python simulate.py examples/hog_cannon_primary.json --out outputs/primary
```

Откройте `outputs/primary/replay.html`: автономный просмотр с паузой, перемоткой,
скоростью, координатами, HP и целями. Сетевых зависимостей у HTML нет.
Setup получает только необходимый закреплённый backend в `.physical_deps/cr-bot`,
либо использует уже загруженный submodule. Допустим `CRBOT_PATH` на checkout той же
версии. Локально изменённый backend отклоняется, чтобы отчёт правильно указывал версию.

## Минимальный JSON

```json
{
  "duration_s": 30,
  "events": [
    {"time": 0, "side": "team", "card": "hog-rider", "x": 14, "y": 17},
    {"time": 2.45, "side": "opponent", "card": "cannon", "x": 9, "y": 10}
  ]
}
```

```shell
python simulate.py my_battle.json --out outputs/my_battle
python simulate.py examples/placements.csv --duration 30 --out outputs/csv
python simulate.py --cards
```

CSV: заголовок `time,side,card,x,y`. Для дополнительной конфигурации используйте JSON.
Строки стабильно сортируются по времени. Две стороны могут действовать одновременно;
две постановки одной стороны в один тик отклоняются.

- `time` — секунды от начала модельного боя, не таймкод видео и не обратный таймер.
  Альтернатива — целочисленный `tick`. Шаг 0,05 с (20 Гц); внесеточное время отклоняется,
  чтобы округление не происходило незаметно. При разметке округляйте осознанно.
- `x`: 0…17 слева направо, `y`: 0…31 сверху вниз. Координата — центр клетки.
  `team` начинает снизу, `opponent` сверху; по умолчанию обе стороны используют
  единую мировую систему (`coordinate_system: "world_cells"`).
- `player_cells` — координаты от лица каждого игрока: у opponent поворачиваются
  обе оси `(17-x,31-y)`.
- `world_mtile` — milli-tiles, только центры клеток, например `(14500,17500)`.
  Произвольные позиции внутри клетки пока не поддерживаются и не округляются скрытно.
- `duration_s` — абсолютный горизонт, по умолчанию 300 с. Бой может закончиться раньше.
  Постановка после завершения боя — ошибка. Горизонт включает минимум один тик после
  последней постановки.
- `--sample-ticks 2` — частота сохранения снимков; физика всегда остаётся 20 Гц.
- `level`: только 11; `ruleset_id`: по умолчанию `2026-08-04-roster`.
  Баланс закреплён, а не автоматически обновлён до текущей игры.
- `seed` фиксирует RNG; по умолчанию 0. Эволюции и способности чемпионов не поддержаны;
  неизвестные карты не заменяются похожими.

## Два режима

| Режим | Данные | Проверка |
|---|---|---|
| `placements` по умолчанию | Карта, время, сторона, клетка | Физика уже принятых игрой постановок и допустимость размещения |
| `match` | Постановки и обе колоды/начальные очереди или checkpoint | Дополнительно рука, цикл, эликсир, отказы действий |

В `placements` рука и эликсир не восстанавливаются и выдаются как `null`.
Это не доказательство законности всех действий игрока. Войска и заклинания создаются
в нормальной фазе действий, до deployment, движения и боя; задержки не обнуляются.

В `match` укажите `team_deck` и `opponent_deck` — по 8 карт в начальном порядке:
первые 4 в руке, остальные в очереди. Можно отдельно указать `team_initial_queue`
и `opponent_initial_queue`, перестановки соответствующих колод. Используйте одинаковые
канонические ID в колоде и очереди. Начальный эликсир 5. Пример: `examples/match.json`.

## Файлы результата

| Файл | Назначение |
|---|---|
| `replay.html` | Автономный просмотр; линии показывают текущие цели |
| `snapshots.jsonl` | Авторитетные состояния по одному JSON на строку |
| `events.jsonl` | Спавны, смены цели, атаки, попадания, смерти, фазы матча |
| `report.json` | Статус, индекс ошибочной постановки, версии/hash, seed, неопределённости карт |
| `checkpoint.json` | Полное состояние, включая таймеры, снаряды, RNG и очередь |

Повторный запуск в ту же папку перезаписывает только эти файлы. Input и исходный
checkpoint нельзя размещать на путях перезаписываемых результатов.

Снимок `tick=N` — состояние до действий N. Событие `tick=N` относится к исполнению
этого тика; результат виден в `state_tick=N+1`. Исключение — начальное `match_started`.
Используйте `damage_applied` для попаданий, а не `attack_started` или счётчик атак.

`horizon_reached` — достигнуто заданное время, `terminal` — бой завершился.
Ни один статус не подтверждает совпадение с видео: `fidelity` остаётся
`unverified_against_real_game`. При ошибке код возврата 2, `status=failed`, частичный
trace сохраняется; такой checkpoint не разрешён для продолжения.

## Продолжение

Создайте новый файл рядом с корнем репозитория:

```json
{
  "mode": "placements",
  "initial_state": "outputs/primary/checkpoint.json",
  "duration_s": 30,
  "events": [
    {"time": 14, "side": "team", "card": "valkyrie", "x": 4, "y": 19}
  ]
}
```

`initial_state` разрешается относительно JSON. Времена оставшихся постановок
и горизонт остаются абсолютными. Сохраняйте продолжение в другую папку.
Проверяются режим, версии runtime/backend/physics profile, hash состояния и правила.
Checkpoint из неполного эпизода не становится полным состоянием реальной игры.

## Проверки

```shell
python compare_demo.py
python -m pip install pytest
```

Из `starter`: `python -m pytest tests -q`.
Из корня с `PYTHONPATH=starter`: `python -m pytest starter/tests tools/cr_hog_fidelity_test/tests -q`.
В PowerShell задайте переменную как `$env:PYTHONPATH='starter'`.

`compare_demo.py` сохраняет сравнение PRIMARY в `outputs/demo_comparison` и возвращает
1 при расхождении. Он проверяет все попадания, включая лишние/недостающие,
и использует события урона и смерти. Это диагностический тест: изолированный вход
пропускает соседний бой, видимый на видео. Подробности — в [аудите](SIMULATOR_AUDIT_RU.md).

Дополнительный независимый эпизод без активных войск на соседней линии:

```shell
python compare_demo.py --input examples/hog_cannon_secondary.json --reference physical_tests/references/d03_hog_cannon_01_secondary.json --out outputs/secondary
```

Разметка SECONDARY хранит наблюдаемые временные интервалы, а не выдает их середины за точные кадры.
